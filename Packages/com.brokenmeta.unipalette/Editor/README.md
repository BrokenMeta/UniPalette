# Editor architecture

The package is being organized into layers incrementally. One Editor assembly still contains all layers.

| Folder / namespace suffix | Responsibility | Main types |
| --- | --- | --- |
| Host | EditorWindow entry point, composition/lifetime, Editor notifications and close-before-execution | UniPaletteWindow |
| Presentation | Visual tree, recycled rows, input routing, browser formatting, session-to-view coordination and focus | PaletteView, PalettePresenter, BrowserPresentation, PaletteRow, UI assets |
| Application | Palette workflow, browser transitions, query/selection, history and source contract | PaletteSession, PaletteBrowser, ContextBrowser, CommandBrowser, PaletteHistory, ICommandSource, IContextSource, IContextSelection |
| Lifetime | Synchronous notifications and owned subscription handles | Signal, Subscription, SubscriptionScope |
| Model | Items, context identity and relationships | PaletteItem, ContextItem, asset/scene/root contexts, menu commands/categories, SearchQuery |
| Services | Unity data access, menu discovery and native dispatch | UnityContexts, UnityContextSource, UnityContextSelection, EditorContext, MenuCommands, NativeExecution |

Internal namespaces follow BrokenMeta.UniPalette.Editor plus the folder name. The public UniPaletteWindow remains in BrokenMeta.UniPalette.Editor to preserve its full type identity for saved Editor layouts and external references.

PaletteSession is the former PaletteState: it coordinates operations as well as holding transient data. Its results List is private; consumers receive one live ReadOnlyCollection through Results, compatible with ListView IList binding but not mutable through it. FindResultIndex provides predicate lookup without exposing the backing List. Only the session changes results and selection. The window owns its command source and creates a UnityContextSelection shared by the session, command discovery and native preparation. The session borrows IContextSelection and the source, and unsubscribes from the source on disposal. Context confirmation happens before requesting commands. UnityContextSelection uses context visitor dispatch to create EditorContext bindings: these own Selection synchronization/matching, live target validation, scene capture and root preparation. NativeExecution retains a binding and captured target/scene through close, focus and dispatch; it never repairs Selection during execution. These services and bindings own no disposable resources. Browser objects represent immutable navigation levels retained in history. ContextBrowser borrows IContextSource, preserves that dependency when opening nested contexts and filters its results without referencing Unity services or inspecting context types. The host provides UnityContextSource, which resolves live roots, enumerates children and determines whether a context opens for browsing. It dispatches native contexts through IContextVisitor and traverses ordinary item trees in their existing order. Models no longer enumerate children or decide navigation child availability; CanBrowse remains presentation/category metadata. Empty folders open commands, while virtual roots remain browsable even when empty. Tests provide their own source through the same required constructor contract; PaletteSession has no fixture-root parameter. The context source owns no disposable resources. SearchQuery is an immutable value describing search input: Text preserves whitespace, IsEmpty recognizes only empty text, and Matches uses ordinal case-insensitive substring comparison. Null UI input normalizes to empty; default(SearchQuery) behaves like SearchQuery.Empty. Query identity remains ordinal and case-sensitive, so a case-only edit still resets row selection. PaletteSession converts incoming text once; browsers receive SearchQuery and the view reads Query.Text. Searchable item text/Current Selection aliases remain browser policy. MenuRelevance owns context menu-family rules through IContextVisitor; discovery and native preparation share it. Family relevance does not read Selection, target validity or menu enabled state, and does not guarantee execution. Model items describe identity/relationships; PaletteView owns actual App UI elements and callbacks. PalettePresenter borrows the view/session, subscribes through methods returning IDisposable and maps input to session actions and rendering. Each consumer owns its subscription handles: the presenter groups them in SubscriptionScope, the session stores its command-source handle, and the window/view group their Editor/UI registrations. Disposal is idempotent and stops callbacks retained in a notification snapshot. Publishers keep private synchronous signals, reject subscriptions after disposal and release listeners on disposal. Temporary ListView selection-handler suppression remains local to rebinding; no callback reconnects after view disposal. No external subscription package or global event registry is involved. The host creates an ordinary BrowserPresentationSelector for each presenter and injects it through the existing IPaletteBrowserVisitor<BrowserPresentation> contract. The selector owns its two formatting instances; there is no global formatting instance or static factory. Formatting and PaletteRow data live in Presentation; Application does not reference them. These formatting objects own no disposable resources. The host disposes the presenter before the view/session/source. Host callbacks provide close, native execution and acknowledgement of the current Editor Selection before rendering.

## Remaining stages

This layout makes current responsibilities visible; strict dependency separation is not complete. Context models still read Unity data for display, validity, relationships and browsing, but no longer change or inspect Selection or prepare native execution. CommandBrowser opens categories and forwards menu leaves through the session; NativeExecution owns relevance and preparation checks at the host boundary. Navigation locations, search aliases and application error messages remain in Application. The host still watches Editor state, validates native execution and closes before dispatch.

Next stages can separate remaining Unity data reads from model descriptions when a concrete use case requires it. Adding another browser requires its visitor dispatch and corresponding presentation selection, keeping the supported browser kinds explicit without runtime type switches in the view. No additional assembly definitions, service registry or MVVM framework are required for these stages.

## Contextual action sources

MenuCommands and ContextActionSource<TContext> implement ICommandSource. The host configures a contextual source for each catalog and passes all sources to PaletteCommands, which owns their lifetimes, forwards notifications, combines loading and errors, and concatenates their trees in order. A contextual source returns an empty tree for unsupported contexts. The host configures whether to show an empty group for each catalog.

Scene View Actions is appended for confirmed scene objects. Asset Actions is appended for confirmed assets only when public type-specific discovery returns actions. Existing main-menu categories, including Assets/*, remain separate. ContextActionItem describes a ContextItem, opaque action name, display group and enabled snapshot, not a main-menu path or retained callback. Group labels are metadata; execution is routed by context type, never label text. Source-specific identity and category restoration preserve same-name commands, search, Enter/click, Alt navigation and history. Alt navigation never runs a leaf. Virtual roots receive no contextual actions and cannot reuse a previous Selection.

ContextActionCatalog<TContext> shares live target/Selection/readiness validation, snapshot creation and fresh handler lookup. SceneViewActionCatalog populates an in-memory DropdownMenu through AddGameObjectEntriesTo. AssetActionCatalog uses AddMenuItemsForType with the actual target.GetType() and target, without a registry of asset types or extensions. These are typed CONTEXT actions, not a complete Project right-click menu. A plain text asset or folder may have no such actions; third-party actions can appear without package changes. Neither path opens a native menu, simulates right click or uses reflection. Catalogs are resource-free instances passed explicitly to discovery and execution.

The host remembers the last active SceneView when UniPalette opens. SceneViewActionExecution requires that explicit view, keeps preparation errors in the palette and never opens or substitutes another view. AssetActionExecution captures the main asset target, validates its GUID-backed context and exact Selection, and focuses Project through the public API. Both consume one execution after closing the palette, rebuild and validate the action again after focus, then invoke its handler once. Missing, ambiguous, disabled or hidden actions are rejected; errors after close go to Console without retry. Selection is never repaired or restored by these paths. Undo/Redo, dialogs and actual effects belong to Unity.

Unity can defer work internally and some handlers use Selection instead of the supplied temporary context. Rebuilding refreshes snapshot flags but does not pin delayed execution or cancel work after handoff. The guarantee is validation at dispatch and one handler invocation, not delayed target stability or a successful result. Some type actions require Inspector or other special UI state. Full Hierarchy/Project context menu discovery remains unverified.

ContextActions tests use the shared disposable scene for the real Scene View close/focus/Duplicate route. AssetActions tests discover real Material actions, verify empty-group behavior, GUID moves, stale/deleted targets and disabled/missing actions. A disposable test ScriptableObject with a non-mutating contextual counter verifies the actual browser close/focus/Project route and repeated-input guard. Tests never open a native menu or execute destructive commands against user data.
